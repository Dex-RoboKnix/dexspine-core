## How do we measure fundamental principles?

We measure the health of the Principles layer using three primary metrics. First is the **"Principle Adherence Rate."** This is a quantitative measure of how many files or tasks in a given track follow the established principles (e.g., naming conventions, Markdown usage, file structure). We aim for 100% adherence in the L0 foundation. Any violation identified during validation is a signal that the principles need better enforcement or clarification.

The second metric is **"Exception Frequency."** While we allow for the "Human Veto," we track how often it is actually used to override a principle. A high exception frequency suggests that a principle is either too rigid, poorly understood, or misaligned with reality. We monitor these "Principle Frictions" to identify candidates for refinement or removal. A stable system is one where principles are followed naturally, without the need for frequent overrides.

Finally, we track **"Rework Caused by Violations."** This is a measure of the cost (in time and compute) of fixing work that was rejected because it violated a core principle. By quantifying the "Cost of Non-Adherence," we can prove the economic value of the principles. A well-principled system should have a decreasing rework rate over time, as both humans and agents become more aligned with the DEX way of building.
