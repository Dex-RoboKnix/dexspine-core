## What is included and excluded?

The scope of the Procedures layer includes all specific, repeatable instructions for discrete system tasks. This covers file creation (naming, directory placement), templating (how to fill each template section), validation (what checks to perform), and reporting (how to log progress in `CASESTUDY.md`). It also includes procedures for directory structure maintenance, version control (commit message formatting), and checkpoint reporting procedures.

Included in the scope are the "1 Task = 1 File" mandate and the specific naming conventions used throughout the spine (e.g., `01_definition.md`, `va.md`, `llm.md`). These are the "Operational Atomics" that ensure every part of the system is built to the same standard. Any task that can be defined as a series of clear, unambiguous steps is within the scope of Layer 05.

Excluded from the scope are high-level system workflows (Layer 04), decision-making logic (Layer 03), or broad principles (Layer 02). For example, the *procedure* for how to name a file is in Layer 05, but the *process* of which files to create in which order is in Layer 04. Similarly, the *policy* of when a file requires human approval is in Layer 03. Procedure is the "Step-by-Step Implementation" layer.
