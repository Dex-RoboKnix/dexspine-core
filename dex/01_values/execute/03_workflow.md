## What is the process?

The workflow for managing Core Values is a high-integrity loop of "Draft, Review, Publish, and Reference." It begins when a need for a value clarification or update is identified—usually triggered by a conflict during a `dexfilter` application. A human operator (Layer 8) drafts the proposed change in a new branch, ensuring the 2-4 paragraph rule is respected and all cross-references are correctly set.

The second stage is "Layer 8 Review." This is a mandatory checkpoint where the proposed changes are audited against the existing foundation. We ask: "Does this new value contradict our existing beliefs? Does it maintain vendor agnosticism? Is it human-readable?" Once approved, the change is merged into the main spine. This "Gatekeeper" step is what prevents "value creep" and ensures the foundation remains irreducible.

The final stage is "Continuous Reference." Once a value is published, it becomes part of the system's active context. Any subsequent task (L1/L2) must include a step to "Reference Values." Agents are instructed to read the relevant `01_values` files before beginning work. This ensures the values are not just archived knowledge, but active participants in every system operation. The workflow is designed to be slow, deliberate, and high-fidelity.
