## What IS system processes of the DEX system?

System Processes in the DEX system are the high-level workflows and staged hierarchies that transform conceptual inputs into structured outputs. While Policies (Layer 03) provide the "rules" for decision-making, Processes provide the "map" for execution. They define the sequences, stages, and handoffs that ensure work moves through the system in a logical, efficient, and irreducible manner.

The core process pattern in DEX is the **Staged Hierarchy: Concept Before Execution**. This process mandates that any project begins with a `spec.md` and a foundational Plan phase before any code or content is generated. Other key processes include the **Plan -> MVE -> Execute Flow** and the **Economic Model Cascade**, which governs how different LLM models are utilized based on task complexity and rate limits.

Processes act as the "Operating Engine" of the system. They ensure that the L0 foundation is not just a static set of documents, but a living infrastructure that actively guides the build process. By defining these processes in the L0 layer, we ensure that every DEX project—regardless of its subject—follows the same high-fidelity lifecycle.
