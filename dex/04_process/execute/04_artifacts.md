## What gets produced?

The primary artifacts produced by the Process layer are the **19 Filter Files** and the **DEXFILTER_APPLICATION.md** for this layer. These documents are the "Workflow Manual" for the system, defining the stages, handoffs, and hierarchies that govern all work. Each file is a tangible record of a specific process point (e.g., `01_definition.md` defines what processes are, `mve/va.md` provides the human justification for them). These files are the "Orchestration Assets" of the system.

Beyond the layer-specific files, this layer produces the **`spec.md`** files for every DEX project. The spec is the "Project DNA" that guides the agent through the build. It is the most critical *dynamic* artifact in the system, providing the instructions that the /conductor executes. The spec file is the "Process Record" that ensures every project follows the established staged hierarchy.

Finally, this layer produces the **Validated File Tree**. Unlike previous layers, which produce conceptual rules, the Process layer produces the actual "Physical Structure" of the project. A correctly organized and populated file tree is the ultimate proof that the system's processes are functioning. The artifacts of the Process layer are the "Tangible Evidence of Progress," ensuring that the system's "Operating Engine" is producing real-world results.
