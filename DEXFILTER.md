# The 8:3:8 Universal Analytical Filter

**Type:** Constitutional Law  
**Scope:** All DEX systems  
**Status:** Operational  

---

## 1. What is Dexfilter?

The `dexfilter` is the primary mechanism for "Reduction by Addition" within the DEX system. It is a universal analytical lens used to define any subject by answering a fixed set of questions and performing specific extractions. By applying the same 19-point structure to different subjects, the filter ensures that any ambiguity is replaced by a structured definition.

A complete filter application results in 19 files:
- **8 Plan Questions**
- **3 MVE Extractions**
- **8 Execute Questions**

The filter is constant; only the subject changes—a process known as "filter sliding."

## 2. The Questions (Plan)

The Plan phase defines the "what" and "why" of the subject.

| # | Point Name | Question |
|---|------------|----------|
| 01 | Definition | What IS the subject? |
| 02 | Purpose | WHY does the subject exist? |
| 03 | Scope | What is included and excluded? |
| 04 | Stakeholders | Who cares about the subject? |
| 05 | Success Criteria | How do we know it works? |
| 06 | Dependencies | What does the subject need? |
| 07 | Constraints | What limits the subject? |
| 08 | Metrics | How do we measure the subject? |

## 3. The Extractions (MVE)

The Minimum Viable Essence (MVE) phase extracts the irreducible core through three lenses.

| File | Type | Extraction Description |
|------|------|------------------------|
| va.md | Values | The core values and beliefs driving this layer. |
| hu.md | Human | Human insights, intuitions, and lived experience. |
| llm.md | LLM | Patterns, structures, and relationships identified by systematic analysis. |

## 4. The Questions (Execute)

The Execute phase defines the "how" and "where" of the subject's implementation.

| # | Point Name | Question |
|---|------------|----------|
| 01 | Approach | How do we implement the subject? |
| 02 | Tools | What tools enable the subject? |
| 03 | Workflow | What is the process or workflow? |
| 04 | Artifacts | What gets produced? |
| 05 | Validation | How do we verify the output? |
| 06 | Rollback | How do we undo or revert changes? |
| 07 | Monitoring | How do we track the subject in operation? |
| 08 | Improvement | How do we improve the subject over time? |

## 5. How Filter Slides

The filter is applied to each of the six layers of the DEX system. In each position, the "Subject" is the layer itself.

| Position | Layer Code | Layer Name | Subject |
|----------|------------|------------|---------|
| 1 of 6 | 01_values | Values | Core values of the DEX system |
| 2 of 6 | 02_principles | Principles | Fundamental principles of the DEX system |
| 3 of 6 | 03_policy | Policy | Decision policies of the DEX system |
| 4 of 6 | 04_process | Process | System processes of the DEX system |
| 5 of 6 | 05_procedure | Procedure | Component procedures of the DEX system |
| 6 of 6 | 06_pattern | Pattern | Execution patterns of the DEX system |

## 6. How to Apply + Guarantee

To apply the dexfilter to a new subject:
1. **Identify the Subject:** Define the boundary of what needs structure.
2. **Invoke the Filter:** Stop binary decision-making.
3. **Execute the Plan:** Answer the 8 plan questions.
4. **Extract the Essence:** Define the 3 MVE components.
5. **Define Execution:** Answer the 8 execute questions.

**The Guarantee:** The filter never returns an undefined state. It never returns 0. It ALWAYS presents a 1—a structured, actionable definition that allows the system to continue.
